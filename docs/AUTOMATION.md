# 自動化の仕組み（オフラインでのバックエンド実行）

このプロジェクトでは、Claude Code のクラウド実行環境（Cowork / Claude Code on the web）の
**Routine（定期実行トリガー）** を使って、ユーザーが PC を閉じていても
バックエンドで自動的にタスクが実行される仕組みを構築している。

## 仕組みの概要

```
┌─────────────────────────────────────────────┐
│  Anthropic のクラウド（常時稼働）              │
│                                             │
│  ① スケジューラーが設定時刻に発火             │
│        ↓                                    │
│  ② 新しいセッション（コンテナ）が起動         │
│     このリポジトリが自動でクローンされる       │
│        ↓                                    │
│  ③ Claude が登録済みのプロンプトを実行        │
│     （コードレビュー・学習の振り返りなど）     │
│        ↓                                    │
│  ④ 結果を通知（プッシュ通知・メール）         │
└─────────────────────────────────────────────┘
```

ポイント：

- **自分の PC は不要**。実行はすべて Anthropic のクラウド上のコンテナで行われる
- 毎回まっさらなセッションが作られ、リポジトリの最新の状態を見て動く
- 実行結果はプッシュ通知やメールで受け取れる

## 現在設定されている Routine

### 自動化（週次学習レビュー）

- **スケジュール**: 毎週月曜 朝7時ごろ（日本時間）。内部設定は UTC の `3 22 * * 0`（日曜 22:03 UTC = 月曜 7:03 JST）
- **やること**:
  1. `learning-log` リポジトリの直近1週間のコミットを確認する
  2. 1週間で学んだことを日本語で要約する
  3. コードを初心者向けにレビューし、改善点があれば指摘する
  4. 次の1週間で学ぶとよいこと・追加するとよい機能を提案する
  5. レビュー結果を `docs/reviews/日付.md` として保存し、main に直接コミットする（記録ルールは `docs/AUDIT.md` 3.1 参照）
- **結果の受け取り**: 実行完了時にプッシュ通知とメールが届く。過去の記録は `docs/reviews/` でいつでも読み返せる

### AI最新情報デイリー

- **スケジュール**: 毎日 朝7時ごろ（日本時間）。内部設定は UTC の `0 22 * * *`（22:00 UTC = 翌朝 7:00 JST）
- **やること**:
  1. WebSearch / WebFetch で直近24時間の AI 最新情報を調査する
  2. **1次情報を最優先**にする（AI 企業の公式ブログ・リリースノート・モデルカード・論文など）。まとめブログなどの3次情報は避け、裏取りできない噂は「未確認の噂」と明記する
  3. トピックごとに「何ができるか」「リリース時期」「初心者が今使うべきか」を1次情報の URL 付きで報告する
  4. レポートの冒頭に、iPhone の読み上げ機能でそのまま聞ける**音声向け1分サマリー**を付ける
  5. レポート全文を `docs/ai-news/日付.md` として保存し、main に直接コミットする（見逃し防止。保持は目安14日、期限切れは監査が削除候補を挙げて master 承認後に削除）
- **結果の受け取り**: 毎朝プッシュ通知とメールでレポートが届く。見逃しても `docs/ai-news/` で約2週間は読み返せる
- **補足**: X（Twitter）はログインが必要なため直接は読めない。X で話題になる情報の元ネタである公式1次情報を直接チェックする方式を採っている。レポート内容の品質は監査対象外だが、記録の有無とルール遵守は監査でチェックされる（`docs/AUDIT.md` 2章参照）

### 監査ウィークリー

- **スケジュール**: 毎週火曜 朝7時ごろ（日本時間）。内部設定は UTC の `10 22 * * 1`（月曜 22:10 UTC = 火曜 7:10 JST）。月曜の週次レビューの翌日に、直近の実行を検証する
- **やること**（基準の詳細は `docs/AUDIT.md` を参照。監査は毎回この文書を読み、その時点の基準で判定する）:
  1. **死活監視**: 週次レビューの記録（`docs/reviews/`）と先週の監査記録（`docs/audit/`）が存在するか確認
  2. **設定ズレ検知**: このドキュメントの記載と実際の Routine 設定の食い違いを確認
  3. **範囲逸脱検知**: 直近1週間の main のコミットを検査し、「絶対禁止（レッドライン）」違反と「要確認(グレーゾーン)」を分類
  4. 監査レポートを `docs/audit/日付.md` に保存し、main に直接コミットする
- **結果の受け取り**: プッシュ通知とメール。正常でも「すべて正常」と明示報告される。要確認事項は master（ユーザー）の判断を仰ぐ形で列挙される

## Routine の管理方法

Claude Code のセッション内で、Claude に日本語で頼めば操作できる。

| やりたいこと | 頼み方の例 |
|---|---|
| 一覧を見る | 「登録されている Routine を一覧して」 |
| スケジュール変更 | 「週次レビューを毎日実行に変えて」 |
| 内容の変更 | 「レビューの内容に○○も追加して」 |
| 一時停止 | 「『自動化』の Routine を一時停止して」 |
| 削除 | 「『自動化』の Routine を削除して」 |
| 今すぐ試す | 「『自動化』の Routine を今すぐ実行して」 |

## 注意事項

- スケジュールは内部的には **UTC（協定世界時）** で管理されている。
  日本時間（JST）は UTC+9 なので、例えば「月曜 7:00 JST」は「日曜 22:00 UTC」になる
- 実行間隔は最短で1時間ごと
- Routine を増やしすぎると通知が多くなるので、まずは週次から始めて様子を見るのがおすすめ
